# 📖 حالات الاستخدام - نظام إدارة الأدمن

## 🎯 سيناريوهات الاستخدام الشائعة

---

## 1️⃣ إدارة البلاغات

### السيناريو 1: حل بلاغ صحيح
**الموقف**: وصل بلاغ عن صنايعي، وبعد التحقق وجدت أن البلاغ صحيح وتم حل المشكلة.

**الخطوات**:
```dart
// 1. افتح قائمة البلاغات المعلقة
Navigator.pushNamed(context, '/admin/user-reports');

// 2. اختر فلتر "معلق" لعرض البلاغات المعلقة فقط

// 3. انقر على البلاغ لعرض التفاصيل
// النظام ينتقل لصفحة تفاصيل البلاغ

// 4. راجع التفاصيل:
// - من المُبلِغ؟
// - ما السبب؟
// - عدد البلاغات الإجمالي للحساب؟

// 5. انقر على "حل البلاغ"

// 6. اكتب تفاصيل الحل:
// "تم التواصل مع الصنايعي وحل المشكلة. تم التحذير."

// 7. تأكيد ✅
```

**النتيجة**:
- حالة البلاغ تتغير إلى "تم الحل"
- يتم حفظ نص الحل وتاريخه ومعرف الأدمن
- البلاغ يختفي من قائمة "معلق"
- يظهر في قائمة "تم الحل"

---

### السيناريو 2: رفض بلاغ غير مبرر
**الموقف**: وصل بلاغ واضح أنه غير صحيح أو حاقد.

**الخطوات**:
```dart
// 1-4. نفس الخطوات السابقة

// 5. انقر على "رفض البلاغ"

// 6. اكتب سبب الرفض:
// "البلاغ غير صحيح. لا يوجد دليل."

// 7. تأكيد ❌
```

**النتيجة**:
- حالة البلاغ تتغير إلى "مرفوض"
- يتم حفظ سبب الرفض
- البلاغ يختفي من قائمة "معلق"

---

### السيناريو 3: حذف حساب متكرر البلاغات
**الموقف**: صنايعي تلقى 5 بلاغات صحيحة، يجب حذف حسابه.

**الخطوات**:
```dart
// 1-4. نفس الخطوات لفتح تفاصيل البلاغ

// 5. لاحظ عداد البلاغات: "5 بلاغ" (لون أحمر)

// 6. انقر على "حذف الحساب المبلغ عنه"

// 7. اقرأ التأكيد: "سيتم تحويل المستخدم لحساب عادي"

// 8. أكد الحذف ✅
```

**النتيجة**:
- `adminStatus` للصنايعي يتغير إلى "deleted"
- `role` في users يتغير من "craftsman" إلى "user"
- حساب الصنايعي يختفي من القوائم العامة
- يظهر في فلتر "محذوف" فقط
- البلاغ يتم حله تلقائياً

---

## 2️⃣ إدارة المستخدمين

### السيناريو 4: قبول صنايعي جديد
**الموقف**: صنايعي سجل حساب جديد وينتظر الموافقة.

**الخطوات**:
```dart
// 1. افتح قائمة المستخدمين (تبويب الصنايعية)
Navigator.pushNamed(
  context,
  '/admin/users-management',
  arguments: {'tab': 0},
);

// 2. اختر فلتر "معلق"

// 3. انقر على الصنايعي الجديد

// 4. راجع المعلومات:
// - الاسم
// - المهنة
// - رقم الهاتف
// - المدينة
// - معرض الأعمال (الصور)

// 5. تأكد أن الصور مناسبة ومتعلقة بالمهنة

// 6. انقر على "قبول" ✅
```

**النتيجة**:
- `adminStatus` يتغير من "pending" إلى "active"
- يتم حفظ آخر إجراء إداري
- الصنايعي يظهر للمستخدمين في التطبيق
- يختفي من فلتر "معلق"

---

### السيناريو 5: رفض صنايعي (بيانات غير كاملة)
**الموقف**: صنايعي سجل بدون صور أو ببيانات ناقصة.

**الخطوات**:
```dart
// 1-4. نفس الخطوات لفتح تفاصيل الصنايعي

// 5. لاحظ أن معرض الأعمال فارغ أو الصور غير مناسبة

// 6. انقر على "رفض" ❌

// 7. اكتب سبب الرفض:
// "يرجى إضافة صور لأعمالك السابقة"

// 8. تأكيد
```

**النتيجة**:
- `adminStatus` يتغير إلى "rejected"
- يتم حفظ سبب الرفض
- الصنايعي لا يظهر للمستخدمين
- يمكن للصنايعي إعادة التسجيل لاحقاً

---

### السيناريو 6: تعليق صنايعي نشط (مؤقتاً)
**الموقف**: صنايعي نشط تلقى بلاغات ونريد تعليقه مؤقتاً للتحقيق.

**الخطوات**:
```dart
// 1-3. افتح تفاصيل الصنايعي النشط

// 4. راجع قائمة البلاغات المتعلقة به

// 5. انقر على "تعليق" ⏸️

// 6. اكتب سبب التعليق:
// "التعليق المؤقت للتحقيق في البلاغات"

// 7. تأكيد
```

**النتيجة**:
- `adminStatus` يتغير إلى "suspended"
- الصنايعي يختفي من التطبيق مؤقتاً
- يمكن تفعيله لاحقاً

---

### السيناريو 7: حظر صنايعي نهائياً
**الموقف**: صنايعي متكرر المشاكل ونريد حظره نهائياً.

**الخطوات**:
```dart
// 1-3. افتح تفاصيل الصنايعي

// 4. راجع السجل: بلاغات متعددة، تم تعليقه سابقاً

// 5. انقر على "حظر" 🚫

// 6. اكتب سبب الحظر:
// "حظر نهائي بسبب تكرار المخالفات"

// 7. تأكيد
```

**النتيجة**:
- `adminStatus` يتغير إلى "banned"
- الصنايعي محظور بشكل دائم
- لا يمكن ظهوره للمستخدمين
- يمكن تفعيله لاحقاً إذا تم حل المشكلة

---

### السيناريو 8: تفعيل صنايعي معلق
**الموقف**: تم حل المشكلة ونريد تفعيل الحساب المعلق.

**الخطوات**:
```dart
// 1. افتح قائمة المستخدمين

// 2. اختر فلتر "معلق" أو "محظور"

// 3. انقر على الصنايعي

// 4. راجع آخر إجراء إداري وسبب التعليق/الحظر

// 5. إذا تم حل المشكلة، انقر على "تفعيل الحساب" ▶️

// 6. تأكيد ✅
```

**النتيجة**:
- `adminStatus` يتغير إلى "active"
- الصنايعي يعود للظهور للمستخدمين
- يتم حفظ إجراء التفعيل

---

### السيناريو 9: حذف صنايعي نهائياً
**الموقف**: صنايعي يجب حذفه (حذف ناعم).

**الخطوات**:
```dart

// 4. انقر على "حذف الحساب نهائياً" 🗑️

// 5. اقرأ التحذير: "سيتم تحويل المستخدم لحساب عادي"

// 6. أكد الحذف

// 7. اكتب سبب الحذف:
// "حذف بناءً على طلب المستخدم"

// 8. تأكيد نهائي ✅
```

**النتيجة**:
- `adminStatus = "deleted"`
- `role` في users يتغير إلى "user"
- يتم حفظ تاريخ ومعرف من قام بالحذف
- الحساب يختفي من القوائم
- يظهر فقط في فلتر "محذوف"

---

**الموقف**: تم حذف حساب بالخطأ ونريد استعادته.

**الخطوات**:
```dart

// 5. انقر على "استعادة الحساب" ↩️

// 6. تأكيد ✅
```

**النتيجة**:
- `adminStatus = "active"`
- `role` يعود إلى "craftsman"
- يتم مسح بيانات الحذف
- الحساب يعود للظهور للمستخدمين

## 5️⃣ سيناريوهات متقدمة

### السيناريو 13: معالجة حالة طوارئ
**الموقف**: صنايعي تلقى 10 بلاغات في يوم واحد.

**الخطوات**:
```dart
// 1. افتح لوحة التحكم - ستظهر تنبيه "البلاغات المعلقة: 10"

// 2. انقر على بطاقة البلاغات

// 3. ستظهر جميع البلاغات، لاحظ أن 10 منها لنفس الصنايعي

// 4. افتح تفاصيل أحد البلاغات

// 5. لاحظ عداد البلاغات باللون الأحمر: "10 بلاغ"

// 6. قرر الإجراء:
//    أ. إذا كانت البلاغات صحيحة: احذف الحساب فوراً
//    ب. إذا كانت غير صحيحة: ارفض جميع البلاغات

// 7. بعد حذف الحساب، جميع البلاغات تُحل تلقائياً
```

## 📊 ملخص الإجراءات المتاحة

| الحالة | الإجراءات المتاحة |
|--------|-------------------|
| **معلق (pending)** | ✅ قبول \| ❌ رفض \| 🗑️ حذف |
| **نشط (active)** | ⏸️ تعليق \| 🚫 حظر \| 🗑️ حذف |
| **مرفوض (rejected)** | ✅ قبول \| 🗑️ حذف |
| **معلق (suspended)** | ▶️ تفعيل \| 🚫 حظر \| 🗑️ حذف |
| **محظور (banned)** | ▶️ تفعيل \| 🗑️ حذف |
| **محذوف (deleted)** | ↩️ استعادة |
